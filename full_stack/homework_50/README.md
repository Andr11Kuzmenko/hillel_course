# Homework 50 — Оптимізація React-додатків через мемоізацію

## Завдання

Створити React-застосунок, що демонструє оптимізацію продуктивності за допомогою
`React.memo`, `useMemo` та `useCallback`.

## Що реалізовано

- Список із **5000 згенерованих товарів** (детермінований генератор, `src/utils/generateProducts.js`).
- Пошук за назвою, фільтр за категорією, сортування (ціна, рейтинг, назва, «score»).
- «Дорога» функція `slowScore` (цикл для кожного товару) — імітація складних обчислень.
- Статистика (кількість, середня ціна/рейтинг, залишок, час фільтрації в мс).
- Обране (♥) та вибір товару кліком.
- Незалежний стан — **лічильник і перемикач теми**, які не стосуються списку.
- **Лічильники рендерів** (жовті бейджі) на кожній панелі та кожному елементі списку,
  а також логи `[render] ...` / `[useMemo] ...` у консолі браузера.

## Де і навіщо використано мемоізацію

| Де | Що | Навіщо |
|----|----|--------|
| `App.jsx` → `filtered` | `useMemo` | Фільтрація + сортування + `slowScore` для тисяч товарів дорогі. Перераховуються лише при зміні `filters`, а не при кліку на лічильник/тему/обране. |
| `App.jsx` → `stats` | `useMemo` | Агрегація залежить тільки від `filtered`; стабільний об'єкт `stats` не ламає `memo` у `Stats`. |
| `App.jsx` → `visibleProducts` | `useMemo` | `slice()` щоразу створює новий масив; без мемоізації `ProductList` рендерився б завжди. |
| `App.jsx` → `selectedProduct` | `useMemo` | Пошук у масиві з 5000 елементів тільки при зміні `selectedId`. |
| `App.jsx` → усі `handle*` | `useCallback` | Функції передаються в memo-компоненти. Нова функція на кожен рендер = нові props = зайвий рендер. Функціональні оновлення стану (`setX(prev => ...)`) дозволяють мати порожній масив залежностей. |
| `ProductItem.jsx` | `React.memo` | При додаванні в обране/виборі товару перерендерюється лише **один** змінений елемент, а не всі 200 видимих. |
| `ProductList.jsx` | `React.memo` | Не рендериться при зміні лічильника або теми. |
| `Filters.jsx`, `Stats.jsx` | `React.memo` | Рендеряться тільки коли змінюються їхні дані. |
| `Counter.jsx` | **без** `memo` (навмисно) | Для порівняння: рендериться при кожному рендері `App`. |

`generateProducts` викликається через ледачу ініціалізацію `useState(() => ...)`, тож дані
створюються один раз.

### Як перевірити

1. Запустіть `npm run dev` і відкрийте консоль браузера.
2. Натискайте «Лічильник» або «Тема» — лічильники рендерів `App` і `Counter` зростають,
   а `Filters`, `Stats`, `ProductList` та елементи списку — **ні**; `[useMemo]` у консолі не з'являється.
3. Натисніть ♡ на товарі — лічильник зростає лише у цього товару (і в `ProductList`/`Stats`, бо змінились `favorites`).
4. Введіть текст у пошук — виконується `filterAndSortProducts` (видно час у статистиці).

> `React.StrictMode` вимкнено навмисно — у dev-режимі він подвоює рендери, що спотворює лічильники.
